### S3 오브젝트 스토리지 설계

- 오브젝트 저장 방식과 조회 절차
  - 블록, 파일, 오브젝트 저장 방식 구분
  - 오브젝트는 버킷과 키로 식별하며 바이트와 메타데이터를 포함
  - PUT 요청 시 기존 바이트 일부 수정 대신 새 바이트 지정 방식 사용
- 버킷 네임 유니크성 및 관리
  - AWS S3는 전 세계적으로 버킷 이름이 유니크해야 함
  - 로컬 환경 미니오 등은 버킷 이름 중복 가능
  - 버킷 이름 중복 방지를 위해 prefix 사용 권장
- 메타데이터와 데이터 저장소 분리
  - 메타데이터는 API 제공 및 권한 관리(IM, Keycloak 등) 담당
  - 데이터 저장소는 실제 바이트 저장 및 복제 관리
    업로드 및 실패 처리
  - 멀티파트 업로드 지원, 파트별 독립 업로드 및 실패 파트 재시도 가능
  - HTTP 200 응답이 반드시 성공을 의미하지 않음
  - 업로드 중단 시 고아 바이트 발생 가능성 존재
  - 메타데이터 커밋 실패 시 클라이언트 성공 판단 불가
- 버전 관리 및 삭제 정책
  - 버전 ID를 통한 오브젝트 버전 관리 및 soft delete 지원
  - 삭제 태그가 있어도 이전 버전은 정책에 따라 보존 가능
  - 가비지 컬렉션과 컴팩션을 통해 불필요 데이터 정리
- 리스트 및 샤딩
  - 키 분산을 위해 해싱 사용하나 prefix 기반 샤딩 시 비용 발생
  - 버킷별 별도 리스트 테이블 운영 권장
- 공개 노트와 책 기준 요구사항
  - 내구성 99.9999%, 가용성 99.99% 목표
  - 연간 100 페타바이트 데이터 처리 가정
  - 평균 오브젝트 크기 약 59.3MB, 소형 20%, 중형 60%, 대형 20% 분포 가정

### 분산 스토리지 내구성 및 복구

- Erasure coding과 복제 전략
  - 기본적으로 3복제(Primary + 2복제) 방식 사용
  - 복제 수 조절 시 비용과 복구 난이도 trade-off 존재
  - Reed-Solomon 기반 erasure coding 사용, RAID5/6와 유사한 페리티 분산
- 장애 대응 및 배치 전략
  - 장애 발생 시 하트비트 모니터링으로 노드 상태 판단
  - 장애 도메인 고려한 데이터 배치 및 복제 위치 분산
  - AWS, 구글 등 클라우드 환경은 availability zone 단위로 배치
  - 배치 서비스는 가상 테이블 형태로 노드와 파티션 관리
- 복구 및 유지보수
  - 디스크 고장 시 페리티를 이용한 데이터 복구 가능
  - 복구 중에도 읽기 가능하나 성능 저하 발생
  - 복구 정책에 따라 복구 조각 수와 페리티 조각 수 결정
- 데이터 파편화 및 최적화
  - 하드디스크 조각모음 필요성 및 SSD와의 차이점
  - 메모리 파편화 문제와 게임 등에서의 영향 사례
  - 디스크 조각모음은 HDD에서 유용, SSD에서는 오히려 성능 저하
- 가용성 및 요청 처리량
  - 초당 약 53 오브젝트 요청 처리 가정
  - 랜덤 IO 병목 현상 존재, SSD 도입 시 개선 가능성
  - 부하 분산 및 리밸런싱 필요성
- 보안 및 권한 관리
  - 버킷 및 키 접근 권한 관리 필수
  - 암호화 및 체크섬 검증, 정기적 배치 검사 수행
  - Keycloak 등 외부 인증 시스템 연동 사례

### GPU 자원 할당과 AI 인프라 운영

- GPU VRAM 할당 문제
  - 쿠버네티스는 GPU 할당 시 VRAM 단위 세부 조절 기능 미지원
  - GPU는 VRAM이 GPU 보드 내에 고정되어 있어 확장 어려움
  - VRAM 자원 낭비 방지를 위한 세분화 할당 필요성 대두
- 쿠버네티스와 쿠버트(KubeVirt) 환경
  - 쿠버트는 쿠버네티스 기반 VM 관리 솔루션으로 AI 인프라에 활용
  - GPU 할당은 대수 단위로만 가능하며 VRAM 세부 조절 미흡
  - AI 추론 인프라에서 GPU 자원 효율적 분배가 현재 연구 중인 과제
- AI 인프라 운영 현황
  - 대규모 AI 인프라에서 GPU VRAM 활용 최적화 필요
  - VRAM 부족 시 다중 GPU 병렬 사용 사례 존재
  - GPU 자원 관리 미흡 시 비용 및 성능 저하 우려
- 기타 인프라 운영 경험
  - 오픈스택과 쿠버네티스 연동 사례
  - GPU 할당 정책 및 YAML 설정 한계
  - AI 인프라 특성상 GPU 자원 관리가 인프라 운영 핵심 과제

  - 소규모 또는 샌드박스 환경에서는 오픈소스 활용
- 유지보수 및 버전 관리

  - 데몬 재시작 및 버전 변경 시 서비스 중단 위험 존재
  - 쿠버네티스 환경에서 PV(Persistent Volume) 관리와 연계 필요
